# Uninstalling DeepEngineers

Generated by `tools/release/gen_uninstall.py` from the installer's manifest format (format 1, `src/DeepEngineers.Launcher/de_install.py`); regenerate it rather than editing it.

DeepEngineers is built to leave every saved setting of both games as it was; the few values that can still change as a side effect are saved by the launcher before the first session and put back (section 1). Everything the installer adds is listed, as it is installed, in `%LOCALAPPDATA%\DeepEngineers\install\install-manifest.json`, and the uninstaller undoes exactly that list, newest change first. Paths below use these names:

- `<Subnautica>`: your Subnautica folder (Steam, Manage, Browse local files).
- `<Pulsar>`: the Pulsar folder the installer used: `%LOCALAPPDATA%\DeepEngineers\Pulsar` when it unpacked Pulsar, or your own Pulsar folder.
- `%APPDATA%`, `%LOCALAPPDATA%`: type them in the Explorer address bar as they are.

## 1. The automatic way

1. Close Space Engineers and Subnautica normally. A game that is still open keeps its plugin locked.
2. Run `Uninstall.cmd` from the DeepEngineers folder. It prints one PASS, WARN or FAIL line per step, then `UNINSTALL PASS` or `UNINSTALL FAIL`.
3. Options (add them after `Uninstall.cmd`): `-DryRun` shows what would be done and changes nothing; `-RemoveWorlds` also deletes a DeepEngineers world you played; `-RemoveBackups` also deletes `%LOCALAPPDATA%\DeepEngineers\backups`; `-KeepData` keeps `%LOCALAPPDATA%\DeepEngineers` (logs, caches).
4. `python -I launcher\de_install.py status` lists the manifest entry by entry against what is on disk, before or after.

What it does, in this order:

1. **Settings.** If DeepEngineers ever ran a session here, the launcher puts back what it saved before the first one: the Subnautica window values in the registry (`HKCU\Software\Unknown Worlds\Subnautica`, `Screenmanager` keys), the Water Mod's `Volume` in `%APPDATA%\SpaceEngineers\Storage\WaterClientSettings.xml` and the audio keys of `%APPDATA%\SpaceEngineers\SpaceEngineers.cfg` (`launcher.py restore-settings --yes`, or `restore-registry --yes` when only the registry was saved). If `%LOCALAPPDATA%\DeepEngineers\restore.json` exists, a session ended badly: start Space Engineers once with DeepEngineers so the plugin writes the Water Mod volume back, or set it again in game with `/wvolume`.
2. **Worlds first.** A DeepEngineers world you played is kept. While any world uses the planet `DE_4546B`, the world mod stays too: **never open such a world without the plugin and the world mod** (the crater's seabed comes from the plugin; ships resting on it would sink).
3. **The manifest, newest entry first** (table below).
4. **DeepEngineers' own data**: `%LOCALAPPDATA%\DeepEngineers\` (the manifest, `paths.json`, downloads, logs, caches, the saved settings), except `backups\` unless `-RemoveBackups`, and except what that folder held before the first install (an earlier DeepEngineers setup's files, named in the manifest's `localBefore`). Uninstall.cmd then deletes `python\` (the interpreter the installer downloaded; it ran the steps above) unless `-KeepData` or something was kept.

## 2. What the manifest records

| Kind | What it is | Uninstall.cmd | By hand |
|---|---|---|---|
| `file` | a file the installer wrote | created: deleted; replaced: the saved original put back (from install\replaced\); present (it was already there, identical): left | delete it, or copy the saved original back over it |
| `dir` | a folder the installer created | removed when empty | delete it once it is empty |
| `tree` | the Pulsar folder the installer unpacked (portable SE plugin loader) | created: deleted with everything in it; present (your own Pulsar): left | delete %LOCALAPPDATA%\DeepEngineers\Pulsar\ (your own Pulsar folder stays) |
| `loader-dir` | Subnautica's BepInEx folder, when the installer put BepInEx there | the files BepInEx writes by itself (log, cache, config) removed, then the empty folders; kept as it is when other mods use BepInEx | delete &lt;Subnautica&gt;\BepInEx\ if no other mod needs it |
| `loader-file` | a file BepInEx writes for our plugin | deleted | delete it |
| `world-local` | the Star System world copy the installer built from your own game files (New Game &gt; Star System &gt; Start lands on 4546B) | deleted | delete %LOCALAPPDATA%\DeepEngineers\worlds\DeepEngineers 4546B\ |
| `entry` | the line &lt;string&gt;DeepEngineers.SE.dll&lt;/string&gt; under &lt;Local&gt; in Pulsar's profile | the line removed (the rest of the file untouched) | open &lt;Pulsar&gt;\Legacy\Profiles\Current.xml in a text editor and remove that one line |
| `world` | the Space Engineers world copied from the template | removed when you never played it; a played world is kept (--remove-worlds deletes it) | delete the world in Space Engineers (Load Game, Delete) when you no longer want it |

## 4. What stays yours

- Your Workshop subscriptions (Water Mod 2200451495, Text HUD API 758597413): unsubscribe in Steam if you no longer want them.
- The Subnautica Freedom save the renderer used: it is a normal save of yours (Steam Cloud keeps a copy).
- Steam's update setting of both games ("Only update this game when I launch it").
- Space Engineers worlds you made with the planet `DE_4546B`.

## 5. Check

- `python -I launcher\de_install.py status` says not installed (no manifest).
- Subnautica started from Steam: no `BepInEx\LogOutput.log` line `Loading [DeepEngineers.SN` (or no BepInEx at all); the folder holds only the game's own files and your saves.
- Space Engineers started from Steam loads a world without the planet and its log (`%APPDATA%\SpaceEngineers\SpaceEngineers_*.log`) has no line starting with `DE.`.
- `WaterClientSettings.xml`, the `SpaceEngineers.cfg` audio keys and the Subnautica registry values equal the values saved before the first session.
